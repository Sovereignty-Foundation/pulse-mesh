# ADR-0019 — A reader table for lossless fan-out

**Status:** Accepted
**Date:** 2026-10-17
**Amended:** 2026-10-17: as built, opening a ring never opens its table, so every open stays exactly as it was. The creating handle holds the table; a writer that opened the ring instead attaches with `PulseRing::attach_readers`, and `register_reader` opens the table itself, waiting briefly for a creator that has made the ring but not yet the table. A reader takes a line by marking it, writing its starting cursor, then publishing its claim, so a writer never counts a claimed line with a stale cursor, and a reader that starts after the writer has gone a ring's worth past its start begins at the write cursor. `RingError::Stalled` carries the slowest line as `slowest_reader`; the table is limited to `MAX_READERS` (4096) lines and its name to 30 bytes, the hub's limit for derived names, which `/pms-<hub>.readers` meets.

## Context

`PulseRing::publish_blocking` keeps the writer's pace to one reader. The ring header has one read cursor (bytes 16..24), and `advance_read_cursor` only moves it forward, so with several readers it follows the furthest and the writer overwrites the slower ones. The fan-out the benches measure rests on a cursor per reader, each on its own cache line (`peripheral/bench`'s `CursorLine`), which the library does not offer. `hft-stages`' `SpmcRing` has a cursor per reader, but in process memory, and its writer never waits for a reader. So a user who needs every reader in every process to see every pulse has no supported way to get it.

## Decision

A ring may carry a reader table: a companion shared-memory object named `<ring name>.readers`, made with the ring by a new constructor, `PulseRing::create_with_readers(name, capacity, max_readers)`. The table has its own 64-byte header (magic `PMRT`, version 1, the most readers it holds, the ring's capacity), stored magic last as every header in the tree is, and one 64-byte line per reader slot. Each line holds a claim word (zero while free, otherwise the claimant's process id and a generation) and the reader's cursor, so no two readers share a cache line. A reader registers by compare-and-swap of a free claim word (`PulseRing::register_reader() -> ReaderSlot`), reads with the existing `read_position` calls, reports with `ReaderSlot::advance(position)`, and frees its line when it drops. On a ring with a table, `publish_blocking` and `publish_batch_blocking` wait for the slowest registered reader. The writer caches the slowest cursor it last saw and scans the table only when that cached cursor stops proving room, as it already does for the single read cursor, so a writer less than a ring ahead of every reader reads no reader line. The ring header and the slot format do not change. A ring without a table behaves as it does today, and a reader that does not register reads as it does today, losing what it is too slow for. A registered reader that dies holds the writer back. When a blocking publish runs out of room, the writer first frees any line whose claimant's process no longer exists (`kill(pid, 0)` failing with `ESRCH`), then waits; `RingError::Stalled` names the slowest line, and `PulseRing::evict_reader(slot)` frees it explicitly.

## Consequences

The fan-out the benches measure becomes a library feature: N readers in N processes each see every pulse, and the writer keeps the slowest one's pace. A blocking publish costs nothing more while the writer is less than a ring ahead of every reader, and a scan of the table's lines when it is not. The companion object is one more name per ring to create, open, supersede and unlink with it. ADR-0015's rules for a ring's name apply to it in the same order, the ring's name going last, and the `.readers` suffix has to fit the platform's name limit (31 bytes on macOS) with the ring's name, which `RingError::NameTooLong` already reports for derived names. Eviction by process id is best effort, since a recycled id looks alive, which is why `evict_reader` is explicit and the timeout stays. A version-2 ring header holding the table was the alternative: one name and one mapping, at the cost of a new layout version, a moved slot offset and a change to every open. It was not taken because the ring and every open stay as they are; nothing rules it out later, when a table could move into a new header in one layout change.
