# ADR-0013 — One shared-memory mechanism

**Status:** Accepted
**Date:** 2026-09-25

## Context

Three tier-1 crates map POSIX shared memory: the SeqLock ring (`core-ring`), the envelope store (`core-store`) and the single-slot region (`core-region`). Each carried its own copy of the same sequence: read `errno`; validate the name; create the object exclusively and abandon it on any later failure; size it and, on Linux, reserve its pages with `posix_fallocate` so a full `/dev/shm` is an error at creation rather than SIGBUS at the first touch; map it. Or: open it, check its length, read its header with `pread(2)` before mapping anything (through a read-only mapping on macOS), wait out a creator that has made the object but not yet published its header, and map it. And at the end, unlink the name only while it still names this object, through a random token written into a reserved header word and read back through the name. The NUMA module in `hft-stages` had a fourth copy of the reservation and its own mapping guard. The copies agreed in substance and differed in detail, every safety review had to read the sequence three times, and a fix to one copy had to be carried to the others by hand. `core-region`, which the crate index describes as the shared-memory wrappers, had no dependents.

## Decision

`core_region::shm` is the one owner of the POSIX calls: `Name` (validation), `Mapping::create_exclusive` (create, size, reserve, map; abandon on failure), `Opened::open` and `Opened::from_fd` (the step between opening and mapping, at which a caller checks the length and reads or waits for its header through the descriptor, before it touches a page), `Opened::map`, `pread_exact`, `with_prefix_mapped`, `reserve_pages`, `size_and_reserve`, `unlink`, `wait_out_creator` and `Mapping::unlink_if_token` (the token protocol at a caller-chosen header word). A `Mapping` unmaps itself when dropped and closes the descriptor it owns; it never unlinks, since the owner decides that before the drop. `PulseRegion`, `PulseRing` and `EnvelopeStore` hold a `Mapping` in place of their pointer, descriptor, name and descriptor-ownership fields and delegate to it; the NUMA module reserves and maps through the module. Every crate keeps its own header layout, geometry checks, marks and error type, and maps the module's errors into its own one for one, so no public function, error variant or message changes. `core-ring` and `core-store` depend on `core-region` (tier 1 on tier 1); `hft-stages` gains the same dependency (tier 3 on tier 1, which the tier rule allows).

## Consequences

The sequence exists once, with one set of safety arguments, and a fix to it reaches every mapped object. The three crates are shorter by their copies. Behaviour is unchanged, shown by the existing ring, store, region, fresh-shm and NUMA tests on macOS and in the Linux container; the module has unit tests of its own for the mechanism (exclusive creation, the open-then-map step, descriptor ownership, the unlink token). Descriptors are closed at the same points as before: the store still closes its descriptor as soon as it is mapped, a ring or region from `open` closes its own when it drops, and a `from_fd` ring closes the caller's only when the caller handed it over. The ring's drop now unlinks its name before it unmaps rather than after, which nothing can observe. The module's error enum is exhaustive on purpose, so a variant added to it later is a compile error in every crate that maps it.
