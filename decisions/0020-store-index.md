# ADR-0020 — An index of recent cursors for the envelope store

**Status:** Accepted
**Date:** 2026-10-17
**Amended:** 2026-10-17: copies that share an id share content, not origin, time or flags (the store's `tests/fetch_at.rs` stores two such copies), so the sentence below that says only `fetch_at` callers could tell which copy `fetch` returns is wrong: a caller of `fetch` that reads those fields sees that it now gets the newest copy the index holds rather than the first in slot order. A caller that needs one copy names its cursor with `fetch_at`, as the hub runtime does; the dev-03 example and the fuzz harness are the only callers of `fetch` by id in the tree, and the harness's oracle now states the index-first rule.

## Context

`EnvelopeStore::fetch(id)` scans every slot from the first, copying and checking each one that might hold the id, so its cost grows with the store's capacity: a hub's default 256 slots is cheap, and a store sized for a long replay window is not. A Pulse can name the cursor its envelope was stored at, and `fetch_at(cursor, id)` reads that one slot, but a reader that has only the id, such as the dev-03 example or a binding that resolves an id from a client, pays the scan. The store has several writers, each claiming a cursor with `fetch_add` and a slot with compare-and-swap (ADR-0011), and every slot can be overwritten a lap later, so an index that must stay exact needs deletions, tombstones and agreement between writers, none of which the store has today.

## Decision

Layout version 3 of the store adds an index that is a hint, never the truth. After the slots comes a table of `B` buckets, recorded in header bytes 40..44. The creator chooses `B`, a power of two from 1 to the capacity rounded up to one; a store made without a choice gets the smallest power of two no smaller than a quarter of its capacity, so every store of one capacity made by default has one layout. An open takes `B` from the header, as it takes the capacity, so no reader needs to know it. Each bucket is 32 bytes holding four `AtomicU64` cursors, each stored plus one so that zero means empty. A writer that publishes an envelope at cursor `c` stores `c + 1` in bucket `hash(id) mod B`, in the entry `c mod 4`, with one relaxed store: no compare-and-swap, no deletion, and no agreement between writers, since a lost or stale entry costs a fallback, not a wrong answer. `fetch(id)` first reads the id's bucket and tries each non-zero cursor, newest first, with `fetch_at(cursor, id)`, which already refuses a cursor whose slot was overwritten or holds another id. Only if none of the four returns the envelope does it fall back to today's scan. A hit costs one bucket line and one slot copy, whatever the capacity. The scan stays, so a miss in the index is never a wrong `None`. `fetch` now returns the newest copy the index finds, which for envelopes that share an id (the same content) may differ from the first slot in scan order. Since no envelope's bytes differ from another's with the same id, only `fetch_at` callers, which already name their copy, could tell. A version-2 store is refused by a version-3 build with `LayoutMismatch { field: "version" }`, as every layout change has been. No store outlives the daemon that made it, so nothing migrates.

## Consequences

Fetch by id is constant time whenever the envelope is among the four newest stores in its bucket, and no worse than today when it is not. A writer pays one extra store, to a line other writers rarely touch, per envelope. The store grows by 32 bytes per bucket: a quarter of the capacity in buckets is 8 bytes per slot on 64 KiB slots, about 0.01%. The size of the index is the creator's choice and four entries per bucket are fixed: a bucket is half a cache line, and a fixed shape keeps every store's index read the same way. Nothing else in the store's contracts moves: the slot format, the canonical envelope bytes, `fetch_at`, `read_since` and the capacity a creator chooses are as they were, and the region grows only by the table.
